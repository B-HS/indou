# Chromium 프리즈 해결 완료 오판

## 무엇을 지적받았나

사용자가 v0.1.7에서도 프리즈가 계속된다며 실제로 무엇을 검증했는지 지적했다.

## 왜 틀렸나

- 자동 키 입력이 일부 누락돼 목표 일반 Chrome 창이 아닌 시크릿 창을 선택한 실행이 있었지만 성공으로 집계했다.
- 전체 창 스크린샷 해시 변화와 `Page Unresponsive` 부재를 WebContents 정상 동작의 충분한 증거로 취급했다.
- 썸네일 off 대조군과 배포본 검증이 사용자의 정확한 재현 순서와 같은 조건이 아니었다.

## 어떻게 고치나

- 선택 직전 스위처 카드와 commit 로그의 window id를 함께 확인한다.
- WebContents 영역의 실제 입력 반응 또는 지속적인 콘텐츠 갱신을 확인한다.
- 대조군은 같은 창, 같은 콘텐츠, 같은 전환 순서에서 한 변수만 바꾼다.
- 재현 실패와 해결 검증을 구분하고 사용자 실기 확인 전에는 완료로 단정하지 않는다.

## 언제 적용하나

창 전환, 포커스, 캡처처럼 자동 입력이 목표 선택을 바꿀 수 있는 실기 회귀 검증에 적용한다.

## 승격 후보

보편적인 검증 원칙이므로 향후 AI 작업 컨벤션의 버그 재현·완료 판정 규칙으로 승격할 가치가 있다. 이번 작업에서는 피드백 기록만 남긴다.
