## ✅ 수정 항목 (A~D)

### A. commit() 비동기 로드 경쟁 + 직전 세션 상태 미초기화 (High) — 버그 3
**대상**: `SwitcherController.swift` (`openSession` 200-212, `commit` 287-296, `closeSession` 298-306)

**증상**: `openSession()` 은 `sessionActive=true`/`windowsLoaded=false` 만 세팅하고 윈도우 로드는
`Task { await loadWindows() }` 로 비동기 수행(SCShareableContent + AX 패스 = 수십~수백 ms). 트리거를
빠르게 탭+릴리즈하면 `handleFlagsChanged → commit()` 이 로드 완료 **전에** 실행된다.
- `commit()` 은 `advance()`/`move()` 와 달리 `windowsLoaded` 가드가 없다.
- `openSession`/`closeSession` 어디서도 `model.windows`/`selectedIndex`/`liveByID` 를 초기화하지 않는다.

→ 결과: (1) 첫 호출이면 빈 목록 → 포커스 없이 dismiss. (2) 2회차부터는 **직전 세션의 선택 창**(이미
닫힌 stale AX 요소)을 포커스. 핵심 제스처(빠른 ⌥Tab)가 동작하지 않거나 엉뚱한 창을 띄움.

**근본 원인**: 동기 키 이벤트(릴리즈)와 비동기 로드의 순서 경쟁 + 세션 경계에서 상태 미초기화.

**수정**:
- `openSession` 에서 `model.windows = []`, `model.selectedIndex = 0`, `liveByID = [:]`, `pendingCommit = false` 로 직전 세션 상태를 초기화.
- `commit()` 에 `guard windowsLoaded else { pendingCommit = true; return }` 추가(세션을 닫지 않고 보류).
- `loadWindows` 가 `windowsLoaded=true`/`selectedIndex` 확정 후 `pendingCommit` 이면 즉시 `commit()` 하고 패널 표시는 생략.

→ `advance()` 의 `pendingSteps` 버퍼링과 동일한 패턴으로 commit 을 지연 처리. 느린 첫 열거에서도 빠른
⌥Tap+릴리즈가 "이전 창"을 정확히 포커스.

### B. 단일 ⌥Tab 미전환 + reverse 미사용 (High) — 버그 1·2
**대상**: `SwitcherController.swift` (`openSession` 200-212, 호출부 140, 선택식 242)

**증상**: 기본 정렬은 `.recentlyFocused`(`lastFocusOrder` 내림차순)라 **index 0 = 현재 활성 창**.
`openSession` 은 `pendingSteps=0` 을 하드코딩하고 여는 키 입력은 advance 하지 않으므로:
- ⌥Tab 을 한 번 탭+릴리즈하면 index 0(현재 창)을 재포커스 → **전환 안 됨**(클래식 alt-tab 핵심 동작 결함).
- `openSession(reverse:)` 의 `reverse` 인자가 **본문에서 전혀 사용되지 않아** ⌥⇧Tab 이 ⌥Tab 과 동일하게 열림(현재 창 선택).

**근본 원인**: 여는 입력을 "첫 advance" 로 카운트하지 않음. reverse 가 초기 선택에 미반영.

**수정**: `openSession` 에서 `pendingSteps = reverse ? -1 : 1`.
- forward: index 1 = 직전 창(클래식 alt-tab).
- reverse: index `count-1` = 마지막 창.
- count==1: index 0(유일 창, 무해).

> 참고: 워크플로우 #10 은 `reverse ? -1 : 0` 을 제안했으나 forward 를 0 으로 두면 버그 1(단일 탭 미전환)이
> 남는다. 독립 분석 기준 forward 도 1 칸 advance 가 맞다.

### C. ThumbnailStore 캐시 무한 증가 + stale 프리뷰 (Medium) — 버그 4
**대상**: `ThumbnailStore.swift` (12, 28-39, 55)

**증상**: `images[WindowID: NSImage]` 에 삽입만 하고 제거가 없다. `clear()` 는 **호출처가 0개**(dead code).
`SwitcherController` 는 단일 장수명 `ThumbnailStore` 를 매 세션 재사용하므로:
- 한 번이라도 보인 창의 `NSImage` 가 앱 종료까지 누적 → 메뉴바 상주 앱에서 **무한 메모리 증가**.
- `requestThumbnails` 는 `images[id] == nil` 일 때만 캡처 → CGWindowID 재활용 시 **죽은 창의 stale 썸네일**을 새 창에 표시, 영원히 갱신 안 됨.

**근본 원인**: 에비ction 미연결. `IconProvider.prune(keeping:)`(매 세션 호출됨)에 대응하는 정리가 없음.

**수정**: `openSession` 에서 `thumbnails.clear()` 호출(새 세션마다 신선 캡처). 세션 중 액션 재열거
(`refreshAfterAction → loadWindows`)는 `clear` 하지 않아 유효 썸네일은 유지. 캐시는 세션 단위로 경계.

### D. AX 열거 메인 스레드 동기 블로킹 (Medium) — 버그 5
**대상**: `WindowEnumerator.swift` (`collectAccessibilityWindows` 120-152), `EventTapController.swift` (41-42)

**증상**: `collectAccessibilityWindows()` 는 동기 함수이고 `@MainActor` 에서 실행된다(`enumerate()` 내
await 없는 구간). 모든 regular 앱·창에 대해 cross-process AX 메시징(앱당 0.5s 타임아웃)을 **메인 스레드에서
블로킹**한다. 이벤트 탭은 `CFRunLoopGetMain()` 에 부착되어 같은 런루프를 공유하므로, 느린 AX 패스 동안
탭 콜백이 지연되고 OS 가 `tapDisabledByTimeout` 으로 탭을 끌 수 있다(아키텍처 문서는 전용 백그라운드
스레드를 계획했으나 구현은 메인 런루프).

**근본 원인**: 무거운 동기 AX 작업이 메인 액터를 점유. (이벤트 탭의 동기 swallow 결정 때문에 탭 자체를
백그라운드로 옮기는 것은 `MainActor.assumeIsolated`/동기 반환 설계를 깨므로 부적합 → **블로킹 원인 제거**가 근본 해결.)

**수정**: AX 패스를 메인 액터 밖으로 이동.
- `enumerate()`(MainActor)에서 `NSWorkspace.shared.runningApplications` 를 먼저 스냅샷(`AppSnapshot` Sendable: pid/name/bundleID).
- `collectAccessibilityWindows(apps:)` 를 `nonisolated async` 로 변경 → 글로벌 실행기에서 off-main 실행(AX C API 는 스레드 안전).
- `AXWindowInfo` 를 `Sendable` 로(이미 `nonisolated(unsafe) let element` 보유).

→ 메인 런루프가 열거 중에도 응답 유지 → 이벤트 탭 비활성 위험 제거. 이벤트 탭은 동기 swallow 요건상
메인 런루프 유지(설계 의도).

## ✅ 추가 수정 항목 (E~J)

### E. 취소되지 않는 reload Task 의 세션 클로버링 (Low~Med)
`SwitcherController.swift`. `openSession`/`refreshAfterAction` 의 `Task { loadWindows }` 가 저장·취소되지
않고 `loadWindows` 의 유일한 가드가 `sessionActive`(세션 식별자 아님)라, 세션1 종료 후 ~180ms 내 세션2가
열리면 세션1 Task 가 resume 하여 세션2 결과를 덮어쓸 수 있다.
**수정**: monotonic `sessionGeneration` 도입. `openSession`/`closeSession` 에서 증가, 각 reload Task 가 시작
시점의 generation 을 캡처, `loadWindows` 가 await 후 `guard sessionActive, generation == sessionGeneration`
으로 stale Task 를 폐기.

### F. ExceptionMatcher.whenNoOpenWindow 도달 불가 (Low)
`ExceptionMatcher.swift`. `appWindowCount == 0` 일 때만 hide 하지만, 리졸버가 평가 대상 창이 속한 앱의 창
**전체**로 카운트를 만들어 항상 `>= 1` → 규칙이 아무것도 숨기지 않음.
**수정**: `WindowFilter.resolve` 가 **열린(비최소화·비숨김) 창만** 카운트(`appOpenWindowCounts`)해서 전달.
이제 모든 창이 최소화된 앱의 창들이 `.whenNoOpenWindow` 로 숨겨짐. 회귀 테스트 2건 추가(FilterTests).

### G. wordStarts 대문자 연속 경계 누락 (Low)
`MatchResult.swift`. camelCase·숫자↔문자 경계는 처리하나 대문자 연속 종료 경계("HTTPServer"의 `S`,
"NSWindow"의 `W`)를 누락 → 해당 단어들의 word-prefix/약어 매칭 실패.
**수정**: `prev`·`cur` 모두 대문자이고 `original[i+1]` 이 소문자면 `cur` 를 word-start 로 표시하는 분기 추가.
회귀 테스트 1건 추가(SearchTests, "HTTPServer").

### H. ShortcutRecorder isRecordingShortcut 고착 → 핫키 영구 비활성 (High)
`ShortcutRecorder.swift`. 레코딩 상태를 `.onChange(of: recording)` 로만 통지 → 무장 후 사이드바 이동/창
닫기로 뷰가 파괴되면 `onRecordingChange(false)` 미전달 → 플래그 영구 true → `handleKeyDown` 항상 false →
전역 핫키 전체 사망.
**수정**: (1) `ShortcutRecorder` 에 `.onDisappear { recording=false; onRecordingChange(false) }`(사이드바
이동 대응). (2) `SettingsWindowController.show` 진입 시 `controller.isRecordingShortcut=false` 리셋 +
`NSWindow.willCloseNotification` 관찰로 창 닫힘 시 클리어(뷰가 retained 라 onDisappear 가 안 오는 경우 대비).

### I. '메뉴바 아이콘 표시' 토글 no-op (Medium)
`AppDelegate.swift`. `general.showMenubarIcon` 을 읽는 코드 없음 → StatusItem 무조건 설치·미제거.
**수정**: `applyMenubarIconVisibility()` 가 설정에 따라 설치/`removeStatusItem`. `observeMenubarIconSetting()`
이 `withObservationTracking` 으로 토글 변경에 반응(one-shot 재무장). 아이콘 숨김 시 진입 경로 확보를 위해
`applicationShouldHandleReopen` 에서 Settings 열기(Finder/relaunch 로 재진입 가능).

### J. MRU 형제 창 역전 (Medium)
`SwitcherController.swift`. `appActivationOrder`·`windowFocusOrder` 가 같은 `orderCounter` 공유 + 포커스 후
앱 활성화 알림이 뒤에 와서 `appActivationOrder[pid]` 가 더 커짐 → 방금 포커스한 창이 같은 앱 형제 창에
역전.
**수정**: `lastFocusedWindow(id,pid)` 추적. 활성화 알림 핸들러에서 활성 앱이 방금 포커스한 창의 앱이면
`windowFocusOrder[id]` 를 한 번 더 증가시킨 카운터로 **재스탬프**해 형제보다 항상 위에 유지.

## 런타임 검증 필요 (1)
**privateFocus 가 `_SLPSSetFrontProcessWithOptions` 의 CGError 를 버리고 항상 success 반환** (Low) —
`PreciseFocus.swift` 43-56. SLPS 경로 성공 여부와 무관하게 `didPrivate=true` 가 되어 공개 폴백이 스킵된다.
다만 이는 **AltTab 기법의 의도된 복제**(실제 포커스 메커니즘은 0xf8 make-key 이벤트 레코드이고, 코드는
SLPS 시퀀스의 모든 상태코드를 일관되게 무시)로, `return true` 는 "메커니즘 가용+발사" 의미. 실제 버그
여부는 비공개 API 런타임 동작에 의존하므로 정적 판정 불가. 제안 수정(`guard err == .success`)은 오히려
make-key 만 성공한 경우 약한 폴백으로 떨어뜨리는 회귀 위험. → **현 상태 유지, 실기 회귀 시 재검토.**

## 오탐 (1)
**EventTapController deinit 부재로 tap/source 누수 + dangling refcon** — 기각. 전제(`passUnretained` refcon,
`takeUnretainedValue`, deinit 없음)는 사실이나, use-after-free 는 `tap != nil` 상태로 컨트롤러가 해제돼야
성립한다. `AppDelegate` 가 컨트롤러를 앱 수명 내내 보유하므로 그 경로가 존재하지 않음 → 실제 버그 아님.
